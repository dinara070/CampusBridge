# CampusBridge

Веб-платформа для управління студентськими хакатонами, челенджами та конкурсами.
Реалізовано на Python + Streamlit + SQLite (один файл `campusbridge.py`).

Головний заклад: **Вінницький державний педагогічний університет ім. М. Коцюбинського**,
факультет математики, фізики і комп'ютерних наук.

## Запуск

```bash
pip install -r requirements.txt
streamlit run campusbridge.py
```

Застосунок відкриється в браузері на `http://localhost:8501`.
База даних `campusbridge.db` (SQLite) створюється автоматично при першому запуску.

## Тестові облікові записи (створюються автоматично при першому запуску)

| Роль | Логін | Пароль |
|---|---|---|
| Адміністратор | `admin` | `admin123` |
| Журі | `jury_demo` | `jury123` |
| Ментор | `mentor_demo` | `mentor123` |
| Учасник | `participant_demo` | `part123` |

Ці ж дані показані у застосунку на сторінці входу (розкривний блок «🔑 Демо-облікові
записи»). Нові акаунти журі та менторів адміністратор надалі створює через розділи
«⚖️ Журі» і «🧑‍🏫 Ментори». Учасники також можуть реєструватися самостійно на вкладці
«Реєстрація учасника» за корпоративною поштою (наприклад, `@vspu.edu.ua`).

## 📅 Календар подій — можливості

- **Пошук і сортування:** текстовий пошук за назвою, описом і регламентом; сортування
  за найближчою датою старту або за розміром призового фонду.
- **Інтерактивна календарна сітка:** вкладка «🗓️ Календарна сітка» показує події
  на місячному/тижневому календарі (компонент `streamlit-calendar`), з окремими
  позначками старту реєстрації, старту події та дедлайну пітчингу.
- **Кнопка «Додати в календар»:** для кожної події можна завантажити `.ics` файл
  з усіма ключовими дедлайнами (старт/кінець реєстрації, старт хакатону, дедлайн
  пітчингу) — файл відкривається одним кліком у Google Calendar, Outlook, Apple Calendar.
- **Банери та промо-відео:** адміністратор може додати посилання на банер (URL
  зображення) і промо-відео (YouTube) при створенні/редагуванні події — вони
  відображаються на картці події та в окремому блоці «🎬 Промо-відео».

## Ролі та можливості
**Адміністратор**
- Конструктор подій: типи подій, номінації, критерії оцінювання, дедлайни, статуси.
- Модерація заявок команд: індивідуальні та масові дії, коментарі.
- Керування журі: створення акаунтів, розподіл за номінаціями, конфлікт інтересів.
- Аналітика: графіки за подіями/факультетами/статусами, виявлення аномальних оцінок.
- Сповіщення: глобальні та таргетовані на конкретну команду.
- Імпорт/експорт: CSV та Excel для подій, команд, оцінок, користувачів.

**Учасник / капітан команди**
- Перегляд календаря подій із фільтрами.
- Створення команди (інвайт-код) або приєднання за кодом.
- Подача проєкту: посилання на репозиторій/відео, PDF-презентація (до 50 МБ),
  версіонування подачі, трекінг статусу.
- Перегляд публічного лідерборду та оголошень.

**Журі / експерт**
- Список призначених команд з матеріалами проєкту.
- Матриця оцінювання за критеріями (слайдери) + текстовий фідбек.
- Автоматична блокировка оцінювання команд свого факультету (конфлікт інтересів).
- **Сліпе оцінювання (double-blind):** якщо в налаштуваннях події увімкнено цю опцію,
  журі бачить лише анонімний код команди (наприклад, «Команда №A1B2») замість назви
  та факультету. Захист від конфлікту інтересів за факультетом продовжує діяти
  автоматично навіть у сліпому режимі.

**Ментор**
- Обліковий запис створює адміністратор (розділ «🧑‍🏫 Ментори»).
- Створює слоти для коротких онлайн-консультацій (Office Hours) прив'язані до події:
  дата, час початку/кінця, місце проведення (Zoom/Meet/офлайн), примітка.
- Бачить свій розклад і статус кожного слота (вільно / заброньовано, якою командою).
- Може видалити ще не заброньований слот.

**Учасник — Office Hours**
- На вкладці «🗓️ Office Hours» команда бачить список вільних слотів консультацій
  менторів для своєї події та може записатись у 1 клік.
- Показується поточний запис (ментор, дата, час, місце) з можливістю скасування,
  після чого слот знову стає вільним для інших команд.

## Примітка щодо зберігання файлів

Для спрощення розгортання презентації (PDF) зберігаються як BLOB у SQLite
(до 50 МБ), а не в S3 — це легко замінити на хмарне сховище пізніше без
зміни решти логіки.
